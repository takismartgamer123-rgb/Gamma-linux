Welcome to Gamma Linux

Gamma Linux is a free and open-source distribution project built around one goal: giving older computers another useful life.

Read this first: Gamma is actively developed. The exact desktop, package set, installer behavior, hardware support and minimum requirements can change between ISO builds. The release notes shipped with the ISO are the final reference for that build.

This documentation covers the common workflow. When instructions on this page differ from the release notes or the scripts in the branch you are using, follow the version-specific project material.

Choose the right edition

Choose by processor architecture first, then consider memory and storage. The figures below are practical targets currently shown by the project website, not guarantees of performance on every PC.

EditionArchitectureRAM targetStorage targetIntended use
Legacy-3232-bit x86 (i386)512 MB+8 GB+Older 32-bit computers
Lite-Ghost64-bit x86 (amd64)1 GB+10 GB+Low-resource 64-bit systems
Pro-MaxMini64-bit x86 (amd64)2 GB+15 GB+Systems with more resources
Compatibility note: A 32-bit processor cannot run an amd64 ISO. A 64-bit processor may support either mode, but the firmware and the ISO boot files must also match. Check your CPU and firmware before downloading.

Edition names and specifications are subject to change. Always read the exact release page before choosing an image.

Download and verify

  1. Open the Gamma Linux Releases page.
  2. Select a published release and confirm that its ISO matches your architecture.
  3. Read the release notes for known issues, login details and installer-specific instructions.
  4. If the release publishes a SHA-256 checksum, calculate the checksum of your downloaded file:
sha256sum Gamma-Linux.iso

Compare the result character-for-character with the checksum published for that exact ISO. Do not assume that every release includes a checksum file.

Download only from the project's official release page or another source explicitly linked by the project.

Installation guide

Back up first. Partitioning and formatting can permanently erase data. Make a separate backup of important files and confirm the target disk before applying any changes.

1. Prepare the USB

Write the downloaded ISO to a USB drive with a suitable image-writing tool such as Rufus or Ventoy. Writing an ISO will normally erase or replace the USB's existing contents. Keep a copy of anything stored on it.

2. Check BIOS or UEFI mode

Use the computer's firmware boot menu and select the USB entry matching the machine's boot mode. Common boot-menu keys include F12, F11, Esc, F8 and F9; the correct key depends on the manufacturer.

3. If Windows is installed on the same PC

For a Windows dual-boot setup, disable Fast Startup and hibernation from an Administrator Command Prompt in Windows:

powercfg /h off

Then perform a full Windows shutdown before booting the Gamma USB. This command disables hibernation as well as Fast Startup. Do not access a hibernated Windows partition from Linux.

4. Test the live environment

Boot Gamma in Live Mode before installing. Check the display, keyboard, touchpad, storage, network and general stability. If a critical device does not work, consult the release notes and report the issue before changing disk partitions.

5. Run the installer

When the live desktop provides the Install Gamma Linux launcher, open it to start Calamares. Review the language, keyboard, disk layout, user and bootloader settings carefully. Read the final summary before confirming installation.

6. Finish

When the installer reports completion, reboot and remove the USB when prompted. If the new system does not boot, record the exact message and firmware mode instead of repeatedly changing partitions.

Build Gamma Linux from source

Build scripts and project configuration are maintained in the source repository. The repository README and the scripts on your selected branch define the actual build process.

The documented workflow is split into numbered stages:

  1. scripts/01-prepare.sh — prepare the base chroot.
  2. scripts/02-install-packages.sh — install edition packages.
  3. scripts/03-install-gamma.sh — install Gamma-specific components.
  4. scripts/04-configure.sh — configure the system.
  5. scripts/05-build-squashfs.sh — create the compressed live filesystem.
  6. scripts/06-build-efi.sh — prepare EFI boot files.
  7. scripts/07-build-iso.sh — create the ISO image.
  8. scripts/08-test.sh — run structural and available QEMU boot checks.

For the documented legacy target, the sequence is:

sudo bash scripts/01-prepare.sh legacy
sudo bash scripts/02-install-packages.sh legacy
sudo bash scripts/03-install-gamma.sh legacy
sudo bash scripts/04-configure.sh legacy
sudo bash scripts/05-build-squashfs.sh legacy
sudo bash scripts/06-build-efi.sh legacy
sudo bash scripts/07-build-iso.sh legacy
bash scripts/08-test.sh legacy

Replace legacy with lite or pro only when those targets exist in the branch being built. Install the host dependencies listed in that branch's README first.

Destructive build step: The documented 01-prepare.sh script removes the repository's chroot/, iso/ and output/ directories before preparing a fresh build. Back up anything important there. Inspect the current script before running it, especially when using a different branch.

Automated checks are useful, but they do not replace testing the live ISO and installer on physical hardware.

Troubleshooting

The USB does not appear in the boot menu

  • Try another USB port, preferably a direct port rather than a hub.
  • Re-create the USB and verify the ISO checksum when one is published.
  • Check whether the firmware is set to Legacy BIOS or UEFI and choose the matching boot entry.

The computer starts but the screen stays black

  • Wait briefly to rule out a slow first boot.
  • Check the release notes for graphics compatibility notes or supported fallback boot options.
  • Record the GPU model and any visible boot messages. Do not apply random kernel parameters without understanding their effect.

The installer cannot see the disk or partitions

  • Stop before formatting or writing a partition table.
  • Confirm that the disk is detected by firmware and that Windows is fully shut down if it is installed.
  • Record the storage model, controller mode and installer message.

Network, Wi-Fi or audio is missing

Some hardware needs firmware or device-specific support. Record the exact device model and check the release notes. Avoid downloading firmware from untrusted websites.

The installed system behaves differently from Live Mode

Report the edition, release, boot mode and steps that reproduce the issue. Include logs where possible, but remove passwords, private keys, serial numbers and other personal data before sharing.

Report a problem

Useful bug reports help reproduce the issue. Include:

  • PC manufacturer and model;
  • CPU architecture and model, RAM amount and storage type;
  • Gamma edition and exact release/build;
  • BIOS or UEFI mode;
  • steps to reproduce the issue and the expected result;
  • relevant logs or a clear screenshot, with personal information removed.

Submit reports through GitHub Issues or email founder@mail.gamma-linux.is-local.org.

Frequently asked questions

Is Gamma Linux free?

Yes. Gamma Linux is a free and open-source project. Check the license file in the repository for the project's licensing terms.

Does every edition support 32-bit computers?

No. The Legacy-32 target is intended for 32-bit x86 hardware. Lite-Ghost and Pro-MaxMini are listed as amd64 targets in the current project documentation.

Are the RAM figures guaranteed minimums?

No. They are practical targets shown by the project. Actual usability depends on the release, hardware, drivers and workload.

Can I install Gamma next to Windows?

Dual boot may be possible, but it requires careful partitioning. Back up first, disable Windows Fast Startup and hibernation, and review every installer change.

Where can I find the newest ISO?

Use the GitHub Releases page. Do not assume that every build target has a published ISO.
